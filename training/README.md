# Netra: plate recogniser training kit

> **Not part of the submitted system.** The final system uses pretrained models only (see `MODELS.md`). This folder is an unused experiment, kept for reference: a small plate recogniser trained from scratch on synthetic plates. It works on its own synthetic data, but it was never tested on real plates and is not used by the app.

Trains a **plate-only** character recogniser (a small CRNN with CTC loss, about 2M parameters) on:

- **synthetic Indian plates**, generated on the fly with perspective (viewing angle), rotation, Gaussian and
  speckle noise, blur and motion blur, low resolution, uneven light and JPEG artefacts, and
- **real labelled plate crops**, if you have them (strongly recommended).

The result is `plate_crnn.onnx`. It outputs per-character probabilities, so the backend's multi-frame
fusion and "unknown, never guessed" logic keep working unchanged.

Files: `plategen.py` (data generator) - `model.py` - `data.py` - `train.py` - `evaluate.py`.

## 1. Setup (Windows, PowerShell)

```powershell
cd training
python -m venv .venv
.venv\Scripts\activate
# install the CUDA build of PyTorch first: pick your CUDA version at https://pytorch.org/get-started/locally/
pip install -r requirements.txt
python -c "import torch; print(torch.cuda.is_available())"   # must print True
```

## 2. Look at the generated data before training anything

```powershell
python plategen.py --preview samples.png --strength 0.8
```

Open `samples.png`. The plates should look like worn, blurry, angled CCTV crops that are *mostly legible*.
For better realism put DIN-like or HSRP-like `.ttf` fonts in a folder and add `--font-dir yourfonts` to every
command below. Only a handful of system fonts are used by default.

## 3. Real labelled crops (recommended)

A recogniser needs **plate crops with the text written down**. Detection-only datasets (just boxes) are no use
for this step. Put everything in one flat folder:

```
real/
  labels.csv          header:  filename,text         e.g.  img_0001.jpg,DL8CAY4767
  img_0001.jpg
  ...
```

Text is upper-cased and anything outside A-Z / 0-9 is dropped. About 10% of the rows (chosen by filename
hash) are held out automatically as the validation split and are never trained on. Check each dataset's
licence before using it.

## 4. Train

```powershell
python train.py --epochs 40 --real-dir real --workers 6        # with real crops
python train.py --epochs 40                                    # synthetic only
```

Outputs go to `checkpoints/`: `best.pt`, `last.pt`, `train_log.jsonl` and **`plate_crnn.onnx`**.
Each epoch prints exact-match accuracy. With `--real-dir` the best model is chosen on the real
validation split. If Windows complains about worker processes, use `--workers 0`.

Lower `--p-real` (default 0.5) if you have very few real crops, so the model does not memorise them.

## 5. Measure it honestly

```powershell
python evaluate.py --real-dir real --split val --onnx checkpoints/plate_crnn.onnx --json eval_real.json
```

This scores the current PP-OCR reader and your model on the same crops: exact match, character accuracy,
"confidently wrong" rate, and accuracy by plate width. **Quote the real-crop numbers.** The synthetic
test (`--synthetic 2000`) is generated by the same code the model trained on, so it flatters the trained
model.

Send back: `checkpoints/plate_crnn.onnx`, `checkpoints/train_log.jsonl`, `eval_real.json`.

## Track B (optional): fine-tune the plate detector

If you have a plate dataset with boxes in YOLO format, fine-tune the existing detector (the file is
`backend/models/plate_s.pt`):

```powershell
yolo detect train model=plate_s.pt data=path\to\data.yaml epochs=50 imgsz=640 batch=16 degrees=8 perspective=0.0005 shear=3 hsv_v=0.4
```

Keep a validation split that is never trained on, and compare recall before and after.

## Rules that keep the numbers honest

1. Never evaluate on crops the model trained on.
2. Training samples are kept *borderline legible* on purpose: teaching the model to read text a human could
   not read makes it guess, and the system's refusal logic depends on honest confidences.
3. The preprocessing in `plategen.to_model_input` (grey, 48x192, scaled to [-1, 1]) is part of the model.
   The backend must use exactly that.
